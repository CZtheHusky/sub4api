## 用量字段不能直接按列名比较

网关将总输入拆成互斥计费桶，而 CLI 的 `input_tokens` 是总输入。本轮比较口径是：

```text
CLI input_tokens = 网关 input_tokens + cache_read_tokens + cache_creation_tokens
CLI cached_input_tokens = 网关 cache_read_tokens
CLI output_tokens = 网关 output_tokens
```

例如网关用量行 `69332` 的非缓存输入为 `3250`、缓存输入为 `90240`、输出为 `295`。CLI 侧存在唯一数字候选 `93490 / 90240 / 295`，其中 `93490 = 3250 + 90240`。这说明两边字段口径不同，不代表网关少记了输入；该例的数字配对仍属于辅助证据。

`token_count` 是客户端状态通知，不是可靠的网络响应完成时间戳。初步按 5 秒邻近窗口配对时，有 20 条通知未匹配；检查后，这 20 条的三元组也各有唯一对应候选，只是通知更晚。全体候选的时间差约为 0.078–96.19 秒。**未将这个差值解释成网络延迟或网关耗时，也没有用放宽时间窗口来宣称独立时序验证通过。**

- 没有前后受控的缓存基线，不能给出缓存效果“无回退”的结论。没有据这些样本修改服务代码或配置。
